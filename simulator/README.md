# 100名玩家实验室

这是开发测试工具，不属于正式游戏内容，不会被游戏场景加载，也不会出现在玩家界面中。

## 设计目标

不是100个随机点击机器人，而是100个需求不同的玩家画像。画像由25类核心玩家 × 4个耐心/设备变体组成，共100人。

覆盖玩家来源与需求：
- 抖音3分钟新客、广告敏感、通勤碎片化、回流玩家
- TapTap经营模拟核心玩家、画面/UI党、数值硬核、养老休闲
- 零氪、轻氪、付费效率
- 装修审美、沙盒建造、餐饮经营深度
- 完全新手、大字体需求、小屏单手、低端机、高端机、平板
- 反复重开、收藏成就、速通效率、漏洞猎人、长线连锁经营

## 检测维度

UI、字体、点击热区、信息密度、导航、流程、新手引导、玩法深度、数值平衡、经济软锁、广告体验、性能、稳定性、无障碍、内容量、重复可玩性、自定义、反馈强度。

## 每次运行

```bash
npm run player-lab
```

会生成：
- simulator/reports/latest.json
- simulator/reports/latest.md

CI自动测试使用：
```bash
node simulator/run100.js --ci
```

CI模式只输出摘要，不写入运行报告，避免把测试报告误打进正式游戏。

## 重要原则

1. 100人画像只在开发项目运行。
2. 不会注册到 sceneManager。
3. 不会被 android/entry.js 打包进正式游戏运行逻辑。
4. 不修改玩家真实存档。
5. 经济探针使用独立 reset + 合成测试店铺。
6. 质量问题不会因为“某个画像不喜欢”就直接判死刑，而是按影响人数、严重度和玩家类型综合排序。

## 研究基线

规则重点吸收：
- TapTap评价中高频出现的：广告频率、运行稳定性、玩法设计、UI设计、操作体验、资源获取、游戏平衡、日常肝度、字体/按钮太小、新手教学啰嗦或讲不清。
- 抖音小游戏官方体验规范中强调的：广告不可误触/强制、按钮生效区域、可返回首页、启动与场景加载性能。
- 模拟经营玩家普遍关心的：因果反馈、策略多样性、避免唯一最优解、可恢复失败、长线目标、数值透明度与自由装修真正影响经营。
