# V0.8.36–V0.8.39 第二阶段首包：玩法串联

本阶段不继续扩充底层数据库，而是开始解决“功能已经很多，但没有串成一套游戏”的问题。

## V0.8.36 完整主循环协调器
统一读取：
- 新游戏流程
- 首店签约与筹备
- 装修 / 设备 / 证照 / 员工
- 试营业
- 正式开业
- 长期经营

新增：
- 当前玩法 phase
- 当前主目标
- 5步目标条
- 阻塞原因
- 推荐入口
- 当前主操作
- 安全修复 `hasShop/currentShopId` 不一致

首页“当前目标”不再自行重复判断，而是直接读取统一主循环。

## V0.8.37 功能入口与权限统一
新增统一入口权限策略：
- 新开局未确认城市：只能走创业开局与系统入口
- 未签门店：城市、商圈、找铺、城市动态可用
- 门店相关页面在没有门店时正式阻止
- 有门店后自动放开筹备、菜单、供应链、员工、经营等入口

`entryRouter` 增加：
- setGuard
- getGuardStatus
- ROUTE_BLOCKED
- 推荐正确入口

所以底部导航、功能中心和其他 sceneManager 跳转都会经过同一个入口规则。

## V0.8.38 交互失败 / 回退系统
新增：
- 关键状态检查
- 安全修复
- 操作异常记录
- 事务快照
- 异常自动回滚
- 业务失败可选回滚
- 最近失败和修复记录

首页主目标操作正式通过该层执行，避免按钮失败后留下半套状态。

## V0.8.39 第一轮数值平衡 / 防卡死
根据：
- 当前现金
- 月租
- 当前员工工资
- 门店生命周期阶段
- 开店贷款
- 统一财务

动态计算：
- 月固定消耗
- 推荐现金储备
- 支出后现金
- 经济紧张度 0–100
- comfortable / balanced / tight / critical
- 资金恢复建议

新增 operationsStore：
- economyBalanceSnapshot
- assessPlannedSpend
- economyRecoveryOptions

原则：
- 不强行禁止正常经营决策
- 真正现金不足才硬阻止
- 接近风险线时给 warning / critical_warning
- 目标是保持“差一点够、但还有补救办法”的经营张力，而不是直接把玩家卡死

基线：V0.8.35
目标：V0.8.39


## r2 历史兼容修正
- 保留 V0.8.14 的 `newGameFlow.getStartupRoute()` 启动契约。
- 新的玩法协调器不替换旧开局判断，而是在其结果基础上给出统一最终路线。
- 该修正不改变 V0.8.36–V0.8.39 的功能范围。
