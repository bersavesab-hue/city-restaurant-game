# 餐饮经营游戏 V0.2 底层重构 · 第一步

本补丁不改现有 UI，不删除旧系统。目标是先建立一个可以长期扩展的底层“组合包内核”，后续房源、人物、NPC、竞对、事件、评价、定价都从统一规则产生，不再在页面里各算各的。

## 这一步解决什么

1. **PackRegistry**：统一注册所有资源包，防止散落巨大 JSON 无法管理。
2. **CompositionEngine**：正式区分三类组合：
   - fixed：不能乱变的事实/硬约束；
   - weighted：受商圈、职业、经营环境影响的概率组合；
   - free：不破坏现实逻辑的自由表现组合。
3. **EntityFactory**：把“人物”和“NPC角色”分离；把“房源模板”和“实际房源实体”分离；竞对也成为真实经营主体。
4. **PricingEngine**：建立成本、市场、客群预算、品牌四锚点推荐价，允许玩家自由定价，并用价格弹性/预算限制计算反馈。
5. **CompetitionEngine**：玩家赚钱不会自动刷敌人；新店进入由需求缺口、利润、饱和度、租金、空置房源、可复制性共同决定。
6. **ReviewEngine**：评价来自味道、性价比、分量、速度、服务、卫生、环境、稳定性八维真实体验。
7. **EventEngine**：事件先检查条件再发生，避免“每天随机抽彩票”。
8. **SeededRng**：世界生成可重放，方便存档、测试与 bug 复现。

## 组合规则

### 固定组合（硬约束）

- 无排烟不能直接经营爆炒/烧烤类。
- 面积决定座位容量上限，小档口不能凭空生成几十个座位。
- 二三层自然进店客流折损；高楼层必须依赖目的性消费/外卖/品牌。
- 商场档口通常燃气概率低、三相电与消防条件较高。
- 人物年龄与岗位基础要求必须成立。

### 权重组合

- 大学城更容易出现年轻消费与小面积餐饮铺，但不是“只能有学生/档口”。
- 不同建筑类型改变排烟、燃气、电力、消防等设施出现概率。
- 房东、租约、瑕疵、人物背景、竞对策略按环境权重生成。

### 自由组合

- 姓名、部分性格、表现性标签可以自由变化，只要不违反硬条件。

## 为什么人物包和 NPC 包必须拆开

`Person` 表示“这个人是谁”，长期存在；`npc_roles` 表示“这个人目前在世界里做什么”。一个厨师以后可以离职、创业，再成为竞对老板，不会被永久锁死成“厨师 NPC”。

## 定价底层（第一版）

推荐价使用四个锚点：

- 成本安全价
- 附近同类成交/有效市场价
- 目标客群预算
- 品牌溢价

玩家可以把价格定在推荐范围之外，系统不禁止。过低会增加销量但挤压贡献利润、加重排队和供应压力；过高会提高消费者期望并降低价格敏感群体购买概率。

外卖完整结算、历史参考价、套餐锚定、促销承担比例会在后续 Pricing V0.3 接入。

## 竞争底层（第一版）

新竞争者进入分数不会只看“玩家利润”。同一高利润店，在高饱和、高租金、没有空铺的商圈，新店进入分数仍可能很低；相反，在需求缺口大、空置铺充足、模式易复制的商圈，进入速度会更快。

## 接入原则

这一步故意不直接替换旧 `citySystem`、`demandSystem`、房源市场和 UI。先保证新内核独立通过测试；下一步才把旧房源生成迁移到 `EntityFactory.createProperty()`，避免一次大改导致现有 APK 失效。
