# “改名 / 保存模板是假按钮”的真实原因

## 代码其实已经写了

当前项目中：

- `storeScene.js` 已经绑定 `shop:rename`
- `renovationScene.js` 已经绑定 `shop:rename`
- `renovationScene.js` 已经绑定 `room:rename:*`
- `renovationScene.js` 已经绑定 `template:save`
- `customizationSystem.js` 已经实现 `renameShop / renameRoom / saveTemplate / applyTemplate / renameTemplate / deleteTemplate`

所以问题不是“没有业务逻辑”。

## 真正断点在 Android 适配层

当前 `src/ui/textInput.js` 优先调用：

`api.showModal({ editable: true })`

但 Android 的 `android/entry.js` 里只有：

- showToast
- storage
- touch

**没有 showModal。**

于是 textInput 只能退回浏览器 `prompt()`。

而当前 APK WebView 只设置了 `WebViewClient`，没有为浏览器 JS 对话框提供完整支持，所以真机上就会出现：

- 点了“改名”像没反应
- 点“保存模板”不能输入模板名称
- 看起来像假按钮

## 本包已附修复

`patch/android/entry.js`

增加了真正的 DOM 输入弹窗：

- editable 输入框
- 手机软键盘
- 确认/取消
- Enter确认
- 返回输入的 content / inputValue / value
- 非editable确认弹窗也兼容

因此这个修复接入项目后：

- 门店改名可以真正输入
- 包厢改名可以真正输入
- 保存模板可以真正命名并保存
- 另存模板可以真正命名
- 其他确认弹窗也能正常工作
