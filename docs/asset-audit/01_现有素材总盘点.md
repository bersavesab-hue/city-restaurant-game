# 现有图片素材总盘点

## 结论先说

**核心四页（城市首页、商圈详情、门店页、装修页）现在不需要继续生图，就已经够做一次真正的高保真实装。**

之前的问题不是“没有图”，而是：

1. 已经有 5 张完整效果图和 2 张大型图集，但没有彻底拆分、建立坐标清单；
2. 一些页面把带文字的效果图直接拿去当运行背景，导致动态文字重叠；
3. 一些运行图是从效果图二次压缩出来的 JPG / WebP，质量下降；
4. 大量小组件其实已经在两张 1122×1402 PNG 图集中，只是没有系统化使用；
5. “改名 / 保存模板”看起来是假按钮，根本原因不是 customizationSystem 没写，而是 Android 适配层没有 `showModal` 可编辑输入能力。

当前 main 分支 assets 下共有：

  - premium 商圈：6

## 本次已经真正拆出来的东西

两张现有图集已按坐标切分：

- UI 图集：**30 个可调用组件**
- 装修图集：**46 个可调用组件**
- 合计：**76 个组件**

同时保留了 `atlas_regions.json`。以后有两种用法：

- 直接使用 `assets/split/...` 下的独立 PNG；
- 或者只加载一张 atlas，通过矩形坐标 `drawImage` 裁切，减少文件数量。

因此用户之前提出的“有些小东西一张图放很多个，只要游戏能拆分”已经具备实现条件。

## 还真正缺哪些图？

缺口主要不在核心四页，而在**后续尚未完整视觉设计的功能页**。

第一版完整可玩建议再补 **34 个逻辑视觉资源**，但不需要做34个独立文件，可以做成 5 张新图集：

- 房源市场：8个（房源缩略图、经纪人、勘察/合同/位置等）
- 设备采购：8个（灶具、冷链、洗消、收银、通风等）
- 证照办理：4个（经营、食品、消防、检查）
- 招聘：6个（店长、厨师、服务、收银、后厨、兼职）
- 菜单+供应链：8个（菜品分类、供应商、仓储、物流）

数据页和系统页原则上以代码UI为主，不必继续堆图片。

## 最终建议的文件规模

不是“需要两百张散图”。

更合适的是：

- 5张整页效果图：只做设计目标
- 2张现有核心图集：直接复用
- 5张未来功能图集：后续再补
- 10~20张场景大图/门店/人物图
- 动态面板、文字、数字、柱状图、进度条全部代码绘制

这样视觉资源逻辑上可以有 150+ 个组件，但实际文件数量仍可控制在几十个。
