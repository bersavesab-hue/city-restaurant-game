# 餐饮经营数据中枢 V1

## 目标

经营模拟里的数字必须回答三个问题：发生了什么、为什么发生、玩家下一步能改什么。
本补丁把数据拆成统一底座和页面职责，避免“同一指标各算一遍”和“所有数据都堆到一个页”。

## 页面分工

| 页面 | 核心问题 | 应展示的主数据 |
|---|---|---|
| 城市地图 | 哪个商圈值得看 | 人口、当前时段需求、客单、饱和度、事件/趋势 |
| 商圈详情 | 这里适不适合开店 | 客群、分时需求、竞争、租金、机会判断、本店对标 |
| 房源详情 | 这个铺面值不值 | 租约、入场现金、面积、餐位、硬件、可见度、后厨、风险 |
| 门店详情 | 今天为什么赚/亏 | 营业额、订单、客单、利润率、漏斗、流失原因、产能、预警 |
| 菜品/研发 | 这道菜该不该卖 | 单价、单份成本、毛利率、销量、利润贡献、评价、生命周期 |
| 供应链 | 买什么、买多少 | 库存金额、周转天数、进价、新鲜度、损耗、缺货、供应商 |
| 员工 | 人够不够、效率如何 | 人工成本率、人效、工时、技能、士气、高峰缺口 |
| 装修 | 布局是否提高产能 | 餐位密度、翻台、厨房能力、利用率、等待、产能流失、投资回报 |
| 数据中枢 | 整体经营是否变好 | 日/周/月对比、损益、现金流、菜品、库存、人效、产能、预警 |
| 排行 | 为什么我排这里 | 名次变化、订单、客单、评分、热度、价格竞争力、分数构成 |
| 事件 | 事件怎么影响经营 | 需求/租金/采购价/客群的量化变化和持续时间 |

## 统一口径

- 营业额 = 完成订单产生的销售收入。
- 客单价 = 营业额 / 完成订单。
- 毛利润 = 营业额 - 食材成本。
- 毛利率 = 毛利润 / 营业额。
- 经营利润 = 毛利润 - 人工 - 水电 - 房租摊销 - 营销 - 损耗 - 维护 - 其他经营费用。
- 经营利润率 = 经营利润 / 营业额。
- 现金流与利润分开：采购、押金、装修、设备等会改变现金，但不一定在当天全部进入利润。
- 顾客转化漏斗 = 商圈需求 → 本店潜在订单 → 产能/库存约束 → 实际订单 → 流失订单。
- 流失原因尽量按缺货、厨房、餐位、等待、价格、品质、其他拆分；无法证明时不虚构。

## 兼容策略

`businessDataHub.js` 会优先读取新数据，同时自动导入旧存档的 `store.dailyHistory`。旧记录缺少的指标显示为 0/未记录，不编造历史数据。
