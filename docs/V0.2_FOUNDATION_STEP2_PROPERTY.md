# V0.2 底层重构 · 第二步：房源包正式迁移

## 本阶段目标
不推翻现有动态房源市场；把旧挂牌统一接入新的“固定 / 权重 / 自由”组合内核，并补齐后续经营必须使用的房源字段。

## 现在每个挂牌新增
- `propertyKind / propertyKindName`：标准化铺型
- `physicalCapacity`：后厨比例、可用堂食面积、实际座位上限
- `restaurantModes`：快餐、粉面、炒菜、烧烤、火锅、饮品、烘焙适配
- `fairMonthlyRent / rentAssessment`：市场参考租金与挂牌偏离
- `startupEstimate`：押付、转让、装修整改、设备、首批食材、流动资金
- `firstStoreScore`：首店适配分
- `v02Tags`：首店友好、低入场成本、重油烟受限等
- `composition`：明确哪些字段固定、哪些权重随机、哪些完全自由

## 强约束
- 无排烟不能判定为可直接经营重油烟炒菜/烧烤。
- 面积过小不能生成离谱座位数。
- 非首层会真实影响自然进店适配。
- 物理条件已有值时永远优先使用原数据，不随机覆盖。

## 权重组合
- 房东类型、合同、瑕疵按现实条件生成，但同一挂牌 seed 永远可重放。
- 不把随机性直接写成“玩家倒霉”；每项都能解释来源。

## 自由组合
- 视觉门脸等不改变经济结果，可以自由随机，用于资源图自由拼装。

## 向后兼容
`propertyAdapterV02.enrichListing()` 保留原挂牌全部字段，只追加/补齐 V0.2 字段，因此旧筛选、旧详情、旧谈判逻辑仍可继续使用。
