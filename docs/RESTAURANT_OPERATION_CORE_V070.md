# V0.7.0 餐饮经营核心底座

这一版把此前已经存在的顾客、食材、菜品、人物包之间缺失的中间层一次性补齐，不改主页UI、不改房源、不改装修。

## 新增核心包

- 供应商包：18类、126个供应商原型、22合作模式、18账期、20配送方式、30报价策略、24议价风格、36供货风险、30关系事件、16合同类型。
- 采购引擎：询价、比价、采购单、收货、自动补货。
- 库存引擎：批次、库区、容量、保质期、先进先出、损耗、报废、库存预警。
- 订单引擎：堂食/自取/外卖通用订单状态机、菜品明细、折扣与合计。
- 厨房引擎：工位、制作票、真实配方耗料、缺料阻断、出餐时间、成品品质。
- 前厅引擎：餐桌、排队、入座、翻台、服务评分。
- 营业结算：真实订单收入、真实食材成本、平台费、包装、固定成本、利润率。
- 评价复购：连接已有顾客记忆系统与评价系统。
- 员工经营：班次、岗位容量、精力、压力、满意度、离职风险、日工资。
- 外卖：平台、佣金、距离、天气、时效、迟到、品质损失。
- 营销：24类活动，影响需求，不直接凭空创造营业额。
- 品牌成长：20级品牌、经验、声望、知名度、多店容量。
- 餐饮事件：60个事件模板，覆盖供应、厨房、员工、顾客、监管、城市、竞品。
- RestaurantRuntime：把“顾客→菜单→订单→库存→厨房→结算→评价复购→品牌成长”串成一条可测试链。

## 已有系统直接复用

- 64类顾客原型
- 食材库
- 96个基础菜品 / 288+ SKU
- NPC人物底座
- 房源、装修、竞品底座

因此本版没有重复造顾客包或食材包。

2. 供应链页
3. 营业/数据页

随后替换门店页当前简化营业公式。


## V0.7.0 首次集成修复

- 自动补货若需求量低于供应商最低起订量，采购层会自动提升到该供应商 MOQ 后再进行比价。
- 顾客选菜返回值按既有 CustomerEngine 契约读取 `chosen.dish.menuItem`，不再误读不存在的 `chosen.menuItem`。
- 回归测试新增低于 MOQ 的补货场景，防止再次出现“库存为空但生成0张采购单”。
